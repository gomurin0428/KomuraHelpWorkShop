Troubleshooting

トラブルシュート

生成した CHM が期待どおりに表示されない場合の確認項目です。

本文だけの画面になる

#WINDOWS、#STRINGS、Contents file の情報が不足すると、HTML Help Viewer はナビゲーションペインなしで開くことがあります。

  • Contents file=toc.hhc が HHP にあるか確認します。
  • toc.hhc が実際に存在するか確認します。
  • 古い生成物を見ている可能性があるため、CHM を閉じてから再コンパイルします。

バージョン 0.1.1 以降では既定ウィンドウと簡易 TOC の生成を追加しています。古い生成物は再コンパイルしてください。

目次や索引が文字化けする

日本語の HHC/HHK は HTML Help Viewer 側で ANSI コードページとして解釈されることがあります。HHP に次を指定してください。

Language=0x0411 Japanese

バージョン 0.1.2 以降では、この LCID に基づいて HHC/HHK と内部文字列を CP932 に変換して格納します。詳しくは 日本語と文字コード を参照してください。

ファイルが表示されない

  • [FILES] に含まれるパスが HHP からの相対パスになっているか確認します。
  • HTML や CSS から参照しているファイルが、実際にディスク上に存在するか確認します。
  • --no-link-scan を付けている場合は、リンク先ファイルも [FILES] に明示します。
  • --verbose を付けて、収集されたファイル一覧を確認します。

CSS や画像が反映されない

HTML 内の相対リンクは、その HTML ファイルがあるフォルダーを基準に解決されます。たとえば topics/usage.html から ../styles/help.css を参照している場合、実ファイルは HHP から見て styles/help.css にある必要があります。

リンクの詳しい規則は ファイル収集とパス を参照してください。

Windows でブロックされる

インターネットやメールから取得した CHM は Windows によってブロックされることがあります。ファイルのプロパティからブロック解除してから開いてください。

中身を確認する

hh.exe -decompile out-dir file.chm

展開できれば、CHM コンテナとしては HTML Help Viewer に認識されています。展開後に toc.hhc、index.hhk、HTML、CSS、画像が入っているか確認します。
